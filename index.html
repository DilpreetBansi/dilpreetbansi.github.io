WebGPU · TypeScript · Postgres

llama-wgsl

A language model running on your GPU, inside the browser.

llama-wgsl downloads SmolLM2 from Hugging Face, streams the weights straight into GPU memory and runs every layer with compute shaders I wrote by hand in WGSL. No server, no WebAssembly, no ML framework: about 1,500 lines of plain JavaScript.

  • Hand-written kernels. Fused QKV and SwiGLU matrix-vector kernels, grouped-query attention, RoPE with a KV cache, and a GPU argmax for greedy decoding.
  • bf16 without shader-f16. Two weights per 32-bit word, widened in registers, so every WebGPU device can run it at half the memory of f32.
  • Checked against transformers. Logits agree within 4.8e-5 and a 32-token greedy reply is identical, token for token.

Yardline

Quoting and ordering for building-supply yards, full stack.

A contractor texts a messy materials list; the rep pastes it in, gets a priced quote in seconds, sends the customer a link, and turns the accepted quote into an order that reserves stock. React and TypeScript on a Hono API and Postgres. The live demo runs the same API and a real Postgres inside your browser.

  • Reads lists the way people write them. “2x6-16' x 24”, “(12) 2x10x12 DF”, “5/8 type x drywall 4x8 - 60 sheets” are matched to the catalog with a confidence level and priced per thousand board feet, with tier and volume discounts and a margin floor.
  • Safe under concurrency. Version checks stop lost updates. Orders reserve stock under row locks with an idempotency key, tested with transactions racing for the last boards on Postgres.
  • Live everywhere. Events publish after commit: Server-Sent Events and LISTEN/NOTIFY on the server, a SharedWorker across tabs in the demo.
